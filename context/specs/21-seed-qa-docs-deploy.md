# Unit 21: Seed Data, QA, Documentation & Deployment

## Goal
Ship-ready project: realistic seed data for demonstrations, a full manual QA pass, final documentation, and deployment.

## Design
No new UI. A `scripts/seed.ts` command and documentation files.

## Implementation

### Seed script (`npm run seed`; `npm run seed:reset` wipes and reseeds; refuses to run when `NODE_ENV=production` unless `--force`)
- **Settings** defaults.
- **Users:** 1 admin (`admin@athenaeum.test`), 2 librarians, 25 members (varied departments; 2 suspended). Known demo password for all seeded accounts documented in README (e.g. `Library@123`). Membership IDs via the real generator.
- **Categories:** 10 (Computer Science, Fiction, Science, History, Philosophy, Business, Mathematics, Literature, Biography, Self-Development) with icons and colors.
- **Books:** ~60 real-looking titles/authors with valid ISBN-13s, descriptions, tags, shelf locations, 1–6 copies, covers: use Cloudinary demo-hosted placeholders or leave empty to showcase generated covers for ~30%. Include a few single-copy books and two archived books.
- **Circulation history (generated through the real services, not raw inserts):** ~80 loans across the last 90 days with backdated issue dates; returned (most), active (~15), overdue (~6) with some producing fines (mix of unpaid, paid, waived); a handful of renewals; 6 reservations (waiting, one ready); wishlists; ~40 reviews (consistent with loans); notifications generated by services.
- Idempotent logic and a printed summary table at the end.

### QA matrix (document results in `docs/qa-checklist.md`)
Test each role × feature: auth, profile/upload, categories, books, catalog, members/team, issue/return/renew (incl. all rejection rules), fines, reservations (queue promotion, expiry), wishlist/reviews, notifications, dashboards, reports/CSV, audit, settings, maintenance. Include: authorization attempts (member hitting staff APIs/pages), concurrency (last copy), suspended-member behaviour, mobile (360px) and dark-mode passes.

### Documentation
- `README.md` (project): overview, features, stack, setup (env vars, Atlas replica set note, Cloudinary account), seed instructions, demo accounts, scripts, project structure, deployment steps, screenshots section.
- `docs/` outputs: ER diagram description (use `data-model.md`), use-case list (from roles/flows), business rules sheet (from `architecture.md`), API reference (from `api-contract.md`), and viva Q&A cheat sheet (10 likely questions with concise answers about architecture choices, transactions, security, and limitations).

### Deployment
- MongoDB Atlas free cluster (network access 0.0.0.0/0 or Vercel IPs), Cloudinary account, Vercel project with env vars, production `JWT_SECRET` (≥32 random chars), `NEXT_PUBLIC_APP_URL`. Optional `vercel.json` cron calling `/api/maintenance/run` daily with `x-cron-secret`.
- Post-deploy smoke test: register, login, upload avatar, issue/return, reserve, fine, report CSV.

## Dependencies
tsx (to run the seed script), @faker-js/faker (dev only, optional).

## Verify when done
- [ ] Fresh database + `npm run seed` produces a fully populated app; every page shows meaningful data.
- [ ] Seed uses real services (loans, fines, reservations are consistent with business rules; `availableCopies` correct for all books).
- [ ] QA matrix completed with all rows passing; defects fixed and re-verified.
